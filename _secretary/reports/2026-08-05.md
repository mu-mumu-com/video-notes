## 依存パッケージの脆弱性
- momemo（静的HTML、package.jsonなし）とKu-sannpuru main以外は`npm install`＋`npm audit`を実行。共通して以下が見つかった。
- **Next.jsベースの6プロジェクト全て（adult-directory / okinawa-navi / bento-order / bizplan-app / shiro-clinic / kuruma-ya）で high 3件**：Next.js（SSRF・画像最適化DoS・内部エンドポイント漏洩など、バージョンにより件数はやや異なる）／PostCSS（XSS・パストラバーサル）／sharp（libvips由来CVE）。原因はNext.js 16.2系に固定されていること。`npm audit fix --force`でnext@16.3.0へ上げれば解消見込み（要ビルド確認）。
- **bento-order・bizplan-appはさらに計11件（moderate 3・high 8）**：上記に加えてundici関連のhigh多数（レスポンス分断・情報漏洩・Cookieインジェクション等）。
- **ig-auto-reply**：hono に moderate 1件（CORSミドルウェアのReDoS）。
- 全プロジェクト共通の根本原因（Next.jsの固定バージョン）が同じなので、まとめて対応すると効率的そう。

## AI活用の提案
- **① npm auditの一括自動修正フロー**：6リポジトリが同じ原因（Next.js固定バージョン）で脆弱性を抱えているので、GitHub Actions＋Claude Code Actionで「`npm audit fix --force`→ビルド確認→問題なければPR作成」を週次で回す仕組みにすると、毎回手動で追いかけなくて済みそうです。
- **② 死活監視の外部化**：今回判明した通り、この秘書の実行環境からは外部サイトへの直接curlがネットワークポリシーで拒否されます。継続的な死活監視をしたいなら、環境のネットワークポリシーでこれらのドメインを許可するか、UptimeRobot / Better StackのようなHomupe専用の無料監視サービス＋ntfy通知に切り替えるのが確実そうです。
- **③ projects.mdとTASK.mdの自動整合性チェック**：今回、bento-order/shiro-clinic/ig-auto-replyでは「本番URL未確定」と projects.md にある一方、各TASK.mdには実際の本番URLが明記済みという食い違いがありました。次回以降、秘書が両者を突き合わせて食い違いを自動検出するようにすると、この手のズレに早く気づけそうです。

いずれも選択肢としての提示です。やるかどうか・優先度は本人判断でお願いします。
