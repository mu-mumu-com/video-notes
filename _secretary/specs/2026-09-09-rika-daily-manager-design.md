# りかちゃん拡張: 日次マネージャー化（朝・昼・夜のブリーフィングと伴走）設計書

作成日: 2026-09-09
関連: `2026-08-19-rika-mentor-secretary-design.md` / memory `rika-mentor-secretary-design` `secretary-agent-build`

## 背景・課題

ユーザーから次の要望があった:

- 朝に「今日の予定・タスク」を **本業／副業／プライベート** の3軸で伝えてほしい。実行アドバイス・進め方のアドバイスも欲しい。
- 夜に KPI 確認・進捗のふりかえりをしてほしい。「マネージャー兼秘書」が欲しい。
- 自分に対してボスマネジメント（自分を厳しく管理）をしてしまい、やる気が続かない。**次にやるべきことの決定と先導をりかちゃんに引き取ってほしい。**
- 「通知が来て終わり」ではなく、こちらの状況を伝えたら**1日の流れを一緒に決めたい**。タスクが無いときは「本当に無いのか」確認してほしい。**昼にも進捗確認**してほしい。
- 本業は業務を担当制にしており、**毎日／週次／月次の定期業務**がある。その通知・消化確認も入れたい。

「りかちゃん」は既に稼働中の基盤がある（週次チェック・情報収集のクラウドルーティン、`rika-line-bot`、`profile.md`、`fukugyo-roadmap.md`）。本設計はゼロから作らず、この上に「日次の伴走」を追加する。

## 決定事項（ユーザーとの合意）

- 方式は **A案（既存インフラ拡張・追加コストほぼゼロ）** で進める。
- 朝の生成は **クラウドルーティン**（Claude Code プラン内、従量課金なし）。通知と対話は **rika-line-bot**（定型 push は無料、対話の返信時のみ小コスト）。
- カレンダー／リマインダーのクラウドからの直接読み取りは不可 → **iPhone ショートカット自動化**でリマインダーを毎朝吸い上げ、本業の単発予定は `agenda.md` に集約。フルなカレンダー連携はローカルでりかちゃんを呼んだ時のみ。
- 接点は **朝・昼・夜の3回 ＋ 返信で対話**。定型 push は無料、返信した時だけ 1往復およそ5〜15円（プロンプトキャッシュで圧縮）。想定上限 月500〜1500円。
- トーンは **決めてあげる＋励ます**。詰問・ダメ出しは禁止。
- C案（自宅 Mac の launchd でローカル起動）は将来オプションとして温存、今回は実装しない。

### 稼働スケジュールの前提

- **本業は月〜金**（土日休み）。本業ブロック（担当業務・定期業務・単発）と本業定期業務の消化確認は **平日のみ**出す。
- **副業・プライベートは毎日**（土日含む）。土日の朝夜ブリーフィングは本業ブロックを省略し、「今日は本業休み。副業とプライベートに使える日」と明示して副業／プライベート中心にする。
- 祝日は当面「平日扱い」でよい（ユーザーが休みなら朝の返信で「今日は休み」と伝えれば、りかちゃんが土日モードに切り替える）。厳密な祝日表は持たない。
- 本業の**週次定期業務のリマインド**は、該当曜日の朝と前営業日の夜に出す（週末には出さない）。**月次定期業務**は月内の平日ベースで、期日の2〜3営業日前から出す。

## スコープ外（今回やらないこと）

- 本業の業務システム（社内ツール・グループウェア等）との連携。りかちゃんは本業の実データを見られない。定期業務の消化は**ユーザーの自己申告**で記録する。
- 競合・市場調査（既存設計と同じくスコープ外）。
- Google カレンダーのクラウドルーティンへの connector 接続（この環境では不可）。
- 音声通知・ボイスクローン連携（別件、`voice-clone-setup`）。
- **クラウドの朝夜ブリーフィング（LINE）に本業ブロックは含めない**（下記2026-09-09改訂を参照）。

## コンポーネント詳細

### 1. `_secretary/work-duties.md`（新規）— 本業の担当業務マスター

本業で自分が担当している定期業務の定義ファイル。**社名・顧客名・具体的な機密内容は書かない**（業務の呼び名だけ。video-notes はプライベートリポジトリだが念のため）。

```markdown
# 本業 担当業務マスター

りかちゃんが朝夜に「今日/今週/今月やる本業の定期業務」を出すための定義。
機密情報は書かない（業務の呼び名だけ）。消化状況は daily/<日付>.md 側に記録する。

## 担当している業務領域（自分がオーナー）
- 〈例〉◯◯の窓口対応
- 〈例〉△△の管理

## 毎日の定期業務
- [毎日] 〈例〉メール・チャットの確認と返信（午前）
- [平日] 〈例〉日報の提出（退勤前）
- [月火水木金] 〈例〉…

## 週次の定期業務
- [月] 〈例〉週次ミーティングの資料準備
- [金] 〈例〉週報の提出
- [毎週] 〈例〉…（曜日不問なら「毎週」）

## 月次の定期業務
- [第1営業日] 〈例〉月次レポート提出
- [25日] 〈例〉…
- [月末] 〈例〉…
```

- 記法: 行頭の `[…]` が発生タイミング。朝ルーティンが当日の曜日・日付（＋簡易的な営業日判定）と照合して「今日該当するもの」を抽出する。
- 判定できない曖昧な指定（「毎月中旬」等）は、りかちゃんが朝に「今週〈…〉のタイミングでは？」と確認する形にフォールバック。
- 初版の中身はユーザーへのヒアリングで作る（実装時タスク）。

### 4. `_secretary/daily/<YYYY-MM-DD>.md`（新規ディレクトリ）— 朝昼夜の記録

1日1ファイル。朝ルーティンが作成、昼は bot が追記しない（LINE push のみ）、夜ルーティンが夜セクションを追記。

```markdown
---
date: 2026-09-10
---

## 朝（07:00 生成）
### 今日の状態
（曜日・平日/土日・月初/月末など。土日は「本業休み」と明記）

### 本業  ※平日のみ。土日はこのセクションごと省略
- 定期業務（今日該当）: 〈work-duties から抽出〉
- 単発: 〈agenda の work: 行〉
- 今日ここだけ守る: 〈1点〉

### 副業（りかちゃんが決めた）
- 今日の最優先: 〈1つだけ〉
- 最初の30分でやること: 〈具体的に〉
- （理由: ロードマップの現在地から）

### プライベート
- 〈agenda の private: 行〉

### りかちゃんから
- 〈励まし・進め方のひとこと。決めてあげる／詰めない〉
- 予定が薄い場合の確認: 〈本業の締切は？リマインダー見た？昨日の積み残しは？〉

## 宣言（ユーザー/対話で確定）
- [ ] 〈タスク1〉
- [ ] 〈タスク2〉

## 昼（13:00 push のみ・記録なし）

## 夜（21:30 生成）
### 宣言タスクの消化
- 〈1/2 完了 など。ユーザー申告 or 未回答なら「未確認」〉

### 本業定期業務の消化確認
- [ ] 〈今日該当した定期業務〉← LINE で「できた？」と聞く

### ロードマップ進捗
- 〈fukugyo-roadmap.md のチェック差分・コミット履歴から〉

### KPI
- 〈kpi.md 最新との比較。古ければ更新依頼〉

### 明日の種
- 〈1行〉
```

- 「宣言タスクの消化率」は、翌朝ルーティンが前日ファイルの `## 宣言` のチェック状態を見て集計する。チェックは夜の LINE 返信（「1,3できた」→ webhook がファイル更新）または手編集で付く。

### 6. 朝ルーティン（新規クラウドルーティン）

- 作成: `RemoteTrigger action:create`。既存ルーティンの `environment_id`（`env_018JLnu98AphHR6nuD8Md58N`）を流用。
- cron: `0 22 * * *`（UTC）= 07:00 JST 毎日
- source: `https://github.com/mu-mumu-com/video-notes` のみ
- allowed_tools: `Bash, Read, Write, Edit, Glob, Grep`（WebSearch 不要）
- model: `claude-sonnet-5`
- プロンプト要点:
  1. video-notes をチェックアウト確認、上記6ファイルを読む
  2. 今日の日付・曜日・月初/月末を判定。**土日か平日かで出力を変える**
  3. 平日のみ: work-duties.md から今日該当する定期業務を抽出し【本業】ブロックを出す。今日/翌営業日が該当曜日の週次業務、期日2〜3営業日前の月次業務もここに含める。土日は【本業】ブロックを出さず「今日は本業休み」と明示
  4. agenda.md の当日ブロックから work:（平日のみ）/private:/reminders: を取り出す
  5. fukugyo-roadmap.md の「現在地」と未完チェックから、副業の**今日の最優先を1つだけ決める**。最初の30分の具体作業まで書く（毎日）
  6. daily/<前回>.md の未消化があれば冒頭で繰り越す
  7. daily/<今日>.md を上記フォーマットで作成・commit・push
  8. トーン厳守（決めてあげる／励ます／詰めない）。通知はしない（bot がやる）
- ネットワーク制限（GitHub 以外不可）は既存ルーティンと同じ前提でプロンプトに明記

### 7. 夜ルーティン（新規クラウドルーティン）

- cron: `30 12 * * *`（UTC）= 21:30 JST 毎日
- 他の設定は朝ルーティンと同じ
- プロンプト要点:
  1. daily/<今日>.md, work-duties.md, fukugyo-roadmap.md, kpi.md を読む
  2. `## 宣言` のチェック状態から消化を集計（未回答なら「未確認」）
  3. 平日のみ: 今日該当した本業定期業務を「できた？」確認リストとして書く（土日はスキップ）
  4. ロードマップのチェック差分・当日コミットから進捗を1〜2行（毎日）
  5. kpi.md 最新ブロックの日付を見て推移コメント or 更新依頼（毎日）
  6. 明日の種を1行（毎日）
  7. 平日の夜: 翌営業日に該当する週次業務、期日が近い月次業務のリマインドを追加。金曜夜は翌週分もまとめて。土日の夜は本業リマインドを出さない
  8. daily/<今日>.md の `## 夜` セクションに追記・commit・push
  9. トーン厳守

### 8. `rika-line-bot`（既存を拡張）

**scheduled.ts の分岐追加:**

**新規エンドポイント `/ingest`（webhook.ts か index.ts にルート追加）:**

## データフロー: 「宣言タスクの消化率」

1. 朝: daily/<今日>.md の `## 宣言` は空 or 朝ルーティンの下書き
2. ユーザーが LINE で「今日はA、B、Cやる」と返信 → webhook が `## 宣言` に3件チェックボックスで書き込み
3. 昼: bot が最優先を再掲して push（記録は変えない）
4. 夜: ユーザーが「AとCできた」と返信 → webhook が該当行を `[x]` に
5. 夜ルーティン（21:30）: その時点のチェック状態で「2/3」と集計
6. 翌朝ルーティン: 前日 `[ ]` の残りを「繰り越し」として当日の本業/副業ブロックに再掲

未回答の日は「未確認」と記録し、責めない（トーン厳守）。

## エラーハンドリング

- daily ファイル未生成で bot リレーが走った場合: push をスキップ、`console.log` のみ（LINE にエラーを出さない）
- クラウドルーティンが push 権限エラー: レポート全文を run ログに残す（既存挙動と同じ）
- iPhone ショートカットの POST 失敗: 端末側で通知。bot 側は 401/400 を返すだけ
- agenda.md / work-duties.md が無い: 朝ルーティンはその軸を「未設定」と出して、セットアップを促す
- LINE 返信の状態更新でファイル競合（同時編集）: github.ts の既存の「取得→更新→PUT」で sha 不一致なら1回リトライ
