# りかちゃん拡張: 統合秘書化(情報収集・分析・実現可能性調査・メンター伴走)設計書

## 背景・課題
ユーザーから「AI系の最新情報や自分に合う考え方・ビジネスを自動で調べ、組み合わせてビジネスモデルを考え、私生活も含めてメンター的に伴走してくれる仕組みが欲しい。情報が多すぎて疲れる」という相談があった。

調査の結果、この要望の骨格にあたる仕組みはすでに部分的に稼働していることが判明した:
- クラウドルーティン「りかちゃん 情報収集」(毎週月曜)がWeb全体を検索し、`_secretary/research-queue.md` に候補を追記(自動保存はしない)
- `/リサーチ` スキルが個別URL・投稿を精査・信憑性評価し、ユーザーの判断で `video-notes/<ジャンル>/` に保存
- りかちゃん(呼び出し制のローカルペルソナ、`agent/secretary/CLAUDE.md`)が複数プロジェクトの状況を把握し、AI活用の提案などをまとめる
- `rika-line-bot`(Cloudflare Workers)が週次(金曜18:20 JST)・月次(1日18:00 JST)でLINEに状況を自動通知

今回はこの既存基盤の上に、次の3点を拡張する:
1. 「自分に合うか」で候補を絞り込む(個人プロファイルに基づく判定)
2. 事業アイデアを「実際にできるか」まで調べてから提示する(実現可能性調査)
3. ビジネスだけでなく私生活・考え方も含めた継続的なメンター伴走を、情報疲れを増やさない形で届ける

## 決定事項(ユーザーとの合意内容)

- **人格は「りかちゃん」1人に集約**する。判断すること・ユーザーと対話することは分割しない。継続的な関係性(ずっと自分を見てきてくれている相手だからこそ相談できる)を守るため。
- **「調べる」系の作業だけを専門エージェントに分業**する。情報収集・実現可能性調査は「事実を淡々と報告する」性質の作業であり、担当が変わっても結果の質に影響しないため分業に向く。
- 私生活の相談も含め、**メンター対話はりかちゃんが直接担当**する。ただし話題に応じてトーン(プロジェクト報告はテキパキ、私生活の相談は温かめ)を切り替える。
- 「自分に合うか」の判定基準は、**ユーザーが最初に書く簡単なプロファイル + りかちゃんが行動(保存したメモ・提案への反応)から学習する** のハイブリッド。プロファイルの自動書き換えはせず、更新は提案ベース。
- 実現可能性調査は「必要なツール・概算費用・難易度」を調べる。競合・市場調査は今回のスコープ外(将来必要になれば追加)。
- 届け方は**定期的にLINEで軽く届く**(呼べば深掘りもできる)。研究キューを全件見せるのではなく、りかちゃんが自分で1〜2件だけ厳選する。

## アーキテクチャ

```
[月曜] 情報収集エージェント(既存クラウドルーティンを拡張)
  → profile.md を参照し、関心領域だけでなく「合いそうか」の一言評価を添えて
     research-queue.md に追記

[ユーザーが /リサーチ で個別に精査・保存]  ※既存のまま変更なし
  → video-notes/<ジャンル>/*.md に蓄積

[りかちゃん呼び出し時(呼びかけ、または週次/月次の自動実行)]
  りかちゃん(統括・判断・対話)
    ├─ research-queue.md / 蓄積メモ / profile.md を読み、
    │   「今のあなたに合いそうな事業アイデア」候補を組み立てる
    ├─ 候補が出たら → 実現可能性調査エージェントを呼び出す(新規)
    │   「ツール・費用・難易度」のレポートを受け取る
    ├─ ideas.md(新規、検討済みアイデアの台帳)と照合し、重複提案を避ける
    └─ 最終的に出す/出さないを りかちゃんが判断

[rika-line-bot(既存を拡張)]
  → りかちゃんの判断結果を「プロジェクト/ビジネス」「私生活・考え方」の
     2セクションで、定期的に軽く(1〜2件)LINEに届ける
  → ユーザーが深掘りしたい場合はチャット/LINEで呼びかけて直接相談
```

## コンポーネント詳細

### 1. 個人プロファイル `_secretary/profile.md`(新規)
- 内容: 強み・興味・大事にしたい価値観・やりたくないこと・今わくわくしていること
- 作成方法: りかちゃん(または本設計の実装時)がユーザーに数問インタビューして叩き台を作る
- 更新方法: 自動書き換えはしない。りかちゃんが「保存したメモの傾向」「提案への反応(やった/やらなかった)」から気づいたことがあれば、次に呼ばれたときに更新を提案する

### 2. 情報収集エージェント(既存クラウドルーティンを拡張)
- 変更点: 収集基準に profile.md を追加参照し、「関心領域に近いか」だけでなく「このプロファイルの人にとって嬉しいか」の一言理由を research-queue.md の各候補に添える
- それ以外(実行タイミング=毎週月曜、書き込み先=research-queue.md、自動保存しない)は現状維持

### 3. 実現可能性調査エージェント(新規)
- 役割: りかちゃんから「このアイデア、実際にできるか調べて」と依頼されたときだけ動く専門役
- 出力: 必要なツール(名称・無料/有料)・概算費用・難易度(非プログラマーでもいけるか)を簡潔にまとめたレポート
- 呼び出しタイミング: りかちゃんが事業アイデアをユーザーに提示する前(常に事前調査してから出す)
- 実装方式は実装計画側で検討(Claude CodeのAgent機能で都度呼び出す委任か、専用の役割定義ファイルを持たせるか)

### 4. 検討済みアイデア台帳 `_secretary/ideas.md`(新規)
- 内容: これまでにりかちゃんが検討・提示したアイデアと、実現可能性調査の結果、ユーザーの反応(やる/やらない/保留)
- 目的: 同じアイデアの重複提案を防ぎ、時間が経ってからの「あのアイデアどうだったっけ」の参照にも使う

### 5. りかちゃん(統括・判断・メンター対話)`agent/secretary/CLAUDE.md` を拡張
- 追加する役割:
  - profile.md / ideas.md を読み込み対象に追加
  - 事業アイデア組み立て → 実現可能性調査エージェント呼び出し → 判断、という一連の流れをオーナーとして進行
  - 「私生活・考え方」セクション: 自己啓発・思考パーツフォルダの新着メモやprofile.mdの関心から、今の状況に合いそうな視点を1つ添える
  - トーン切り替え: プロジェクト/ビジネス報告は現状のテキパキした調子、私生活の相談は温かめの調子
- 変更しない: 「判断はユーザーに委ねる、りかちゃんは材料を揃えて提案する人」という基本姿勢

### 6. 届け方 `rika-line-bot` を拡張
- 既存の週次(金曜18:20 JST)・月次(1日18:00 JST)通知のメッセージ構成を、「プロジェクト/ビジネス」「私生活・考え方」の2セクションに変更
- research-queue.md の全件を見せず、りかちゃんが厳選した1〜2件のみ載せる
- 深掘りしたい相談は、既存通り呼びかけて(LINE経由のQ&A、またはこのチャット)自由に話せる

## 影響範囲(触るファイル・システム)
- 新規: `video-notes/_secretary/profile.md`, `video-notes/_secretary/ideas.md`
- 更新: `agent/secretary/CLAUDE.md`(りかちゃんの役割定義)
- 更新: クラウドルーティン「りかちゃん 情報収集」の指示内容(profile.md参照の追加)
- 更新: `agent/rika-line-bot/src/`(2セクション構成・厳選ロジックの追加、コード変更を伴う)

## スコープ外(今回やらないこと)
- 事業アイデアの競合・市場調査(将来的な拡張候補)
- 私生活メンター役を別人格に分離すること(継続的な関係性を優先し見送り)
- research-queue.mdの全件をユーザーが手動で読みに行く運用は残すが、それを前提にしない設計にする(厳選プッシュが主動線)
